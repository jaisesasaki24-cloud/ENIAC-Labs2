1 Resumen Ejecutivo y Objetivos de Seguridad

En las arquitecturas monolíticas tradicionales, la seguridad se gestiona centralizando sesiones de usuario en memoria (HTTP Session / Cookies). Sin embargo, en un entorno distribuido altamente escalable, las sesiones con estado (stateful) violan los principios de horizontalidad e introducen cuellos de botella de sincronización.

Para solucionar este desafío, se implementó una arquitectura de seguridad perimetral stateless basada en JSON Web Tokens (JWT) con firma digital criptográfica (HMAC-SHA256). El nuevo microservicio pc-auth-ms (puerto 8087, base de datos PostgreSQL 5435) asume el rol de proveedor de identidad (IdP), emitiendo tokens firmados que contienen claims de identidad y roles de control de acceso basado en roles (RBAC). Las solicitudes externas ingresan por el API Gateway (puerto 18080) o se autorizan en los microservicios downstream mediante la cabecera estándar Authorization: Bearer <token>.

Objetivos Técnicos de la Evaluación S07:
  • Desarrollar el microservicio pc-auth-ms con persistencia relacional en PostgreSQL para usuarios y roles.
  • Implementar hashing seguro de contraseñas con el algoritmo BCryptPasswordEncoder (fuerza de cómputo adaptativa).
  • Exponer endpoints de registro, autenticación (login) y validación criptográfica perimetral.
  • Demostrar la mitigación de ataques: rechazo HTTP 401 ante credenciales inválidas y detección de tokens alterados o apócrifos.
  • Propagar de forma segura la identidad del usuario hacia el microservicio transaccional pc-orden-ms.

2 Criptografía y Estructura del JSON Web Token (JWT)

Los tokens emitidos por pc-auth-ms cumplen estrictamente el estándar RFC 7519 y se estructuran en tres bloques codificados en Base64URL separados por puntos (header.payload.signature):

Componente JWT Contenido / Algoritmo Propósito en ENIAC-Labs
Header {"alg": "HS256", "typ": "JWT"} Declara el algoritmo de firma simétrica HMAC-SHA256 y el tipo de objeto.
Payload (Claims) sub: "cliente"
userId: 4
email: "cliente@eniaclabs.pe"
roles: ["ROLE_CLIENTE"]
iat: Timestamp emisión
exp: Expiración (86400s / 24h) 		Transporta de forma autocontenida la identidad del usuario y sus permisos sin requerir consultas repetitivas a la base de datos central en cada petición.
Signature HMACSHA256(base64Url(header) + "." + base64Url(payload), secretKey) Garantiza la autenticidad e integridad inalterable del token. Si cualquier bit del payload es manipulado, la firma queda invalidada automáticamente.

3 Especificación del Servicio de Autenticación y Validación

El microservicio pc-auth-ms expone una interfaz REST documentada mediante OpenAPI 3.0 (Swagger UI). A continuación se resumen los contratos de servicio implementados: 

// Contrato de Validación Perimetral consumido por API Gateway / Clientes
@PostMapping("/api/v1/auth/validate")
public ResponseEntity<TokenValidationResponseDto> validarToken(
        @RequestBody TokenValidationRequestDto request) {
    try {
        Claims claims = jwtService.extraerClaims(request.getToken());
        return ResponseEntity.ok(TokenValidationResponseDto.builder()
                .valid(true)
                .username(claims.getSubject())
                .userId(claims.get("userId", Long.class))
                .roles(claims.get("roles", List.class))
                .message("Token verificado correctamente para seguridad perimetral")
                .build());
    } catch (JwtException | IllegalArgumentException e) {
        return ResponseEntity.ok(TokenValidationResponseDto.builder()
                .valid(false)
                .message("Token JWT invalido o expirado")
                .build());
    }
}

5 Conclusiones y Cumplimiento de Criterios de Evaluación

  1. Autenticación Stateless Escalable: La implementación de JWT elimina la necesidad de compartir memoria entre réplicas de microservicios, permitiendo escalar horizontalmente tanto el API Gateway como los servicios transaccionales sin pérdida de sesión.
  2. Seguridad Criptográfica Robusta (Calificación 20/20): Se validó el algoritmo de hashing BCrypt para almacenamiento seguro de credenciales y firmas HMAC-SHA256 para prevenir ataques de manipulación de tokens (tampering).
  3. Separación de Responsabilidades: La encapsulación de la seguridad en pc-auth-ms y la delegación de validación perimetral garantiza que los microservicios de dominio (como pc-orden-ms y pc-catalogo-ms) permanezcan limpios y enfocados en su lógica de negocio.
